AgentOS — mistakes found from the owner's phone session (2026-10-06, ~19:00)
Each one is fixed with a GENERAL fix (no task-specific code), then re-tested. Status is updated here as I go.

M1  "Where are you opening YouTube?" was treated as an ORDER and changed the task's course.
    Cause:  every message sent while a task runs became a mid-run "steer", even a question.
    Fix:    questions to a running task get an ANSWER (what it is doing right now, which browser/profile, which
            step) and the plan is NOT changed. "stop"/"cancel" stops it. Only real instructions change course.
    Status: FIXED IN CODE + unit-tested (live re-test pending)

M2  It switched to Chrome profile "asdf" without being asked.
    Cause:  the asdf profile, saved during the LeetCode runs, was applied to EVERY browser task (global preference).
    Fix:    a saved profile only applies to the site/task it was saved for (e.g. leetcode). Otherwise use what the
            owner named in THIS message; if nothing was named, never pick one of the owner's real profiles silently.
    Status: FIXED IN CODE + unit-tested (live re-test pending)

M3  "Open YouTube and play a song" never played anything — the browser agent clicked the search box 8 times and
    never typed.
    Cause:  clicking an input doesn't change the page, so it kept "trying again" on other refs; it never used type.
    Fix:    (a) "search X on <site>" goes straight to the site's search-results URL; (b) to search, use
            type{ref,text,submit} directly (no click first); (c) a click with no effect on an input is followed by
            typing, never by more clicks; (d) "play" is verified by the URL being a video page (/watch) and the
            player playing.
    Status: FIXED IN CODE + unit-tested (live re-test pending)

M4  Second try failed instantly: "'default' is your real Chrome profile" — but the first try used the same
    "default" fine.
    Cause:  name clash — AgentOS's own browser profile is called "default" and Chrome's own first profile is
            "Default". The safety check confused them.
    Fix:    AgentOS's own profile is never treated as a real Chrome profile; only names the owner actually has in
            Chrome (asdf, Challa, ...) or "my default/main Chrome" count as real.
    Status: FIXED IN CODE + unit-tested (live re-test pending)

M5  All 4 steps failed and the review still said "satisfied".
    Cause:  the reviewer model said satisfied; nothing double-checked it.
    Fix:    the review can't be satisfied while steps failed and a different strategy is still possible; it must
            add follow-ups (until the retry limit), and the final answer must say clearly it failed.
    Status: FIXED IN CODE + unit-tested (live re-test pending)

M6  The Computer Agent "located" the address bar of the WRONG window (the owner's Brave with AgentOS) and
    acted there.
    Cause:  locate/screenshot looks at the whole screen; the target Chrome window wasn't in front.
    Fix:    before locate/click/paste the target window is brought to the front and checked; the vision model is
            told which window to look at, and results outside that window are rejected.
    Status: FIXED IN CODE + unit-tested (live re-test pending)

M7  It took over the owner's mouse/keyboard while they were using the laptop (owner wants both working at once).
    Cause:  the Computer Agent drives the real mouse/keyboard; the only protection was waiting for idle.
    Fix:    researched solution (see below, M7 notes): drive the owner's real Chrome WITHOUT the mouse/keyboard —
            through the AgentOS Chrome extension (chrome.debugger / CDP inside the owner's own Chrome profile, in a
            background tab or separate window), so agent and owner work at the same time.
    Status: OPEN (research in progress)

M8  It typed the URL letter by letter ("https://www.youtube.com\n") instead of pasting it.
    Cause:  this run was started before the new open_url action was loaded.
    Fix:    open_url (Ctrl+L, paste, Enter, check the address bar) — already written; needs a restart + test.
    Status: FIXED IN CODE, NOT YET RE-TESTED

M9  (owner request) AgentOS should send SCREENSHOTS and its current status to the owner's phone when useful.
    Fix:    ntfy image attachments: (a) a `phone_update(text, screenshot)` tool any agent can use when it wants to
            show progress; (b) asking a running task "status?"/"what are you doing" from the phone answers with the

    Status: FIXED IN CODE + unit-tested (live re-test pending)
